1. 项目概述与总体拓扑

ESP32_COMM 是机器人 DCU（Domain Control Unit，域控制器）板上的 ESP32-C3 固件，承担三类职责：

① OTA 中继枢纽：上位机通过 WiFi（HTTP）或 BLE（GATT）把固件交给 ESP32；ESP32 自身固件写入 AB 双分区升级， GD32 固件缓存到本地 Flash 后经 SPI 安全通道转发烧写，电机节点固件经 GD32 的 CAN 总线二次中继。

② SPI Link v2 主站：以 13.33 MHz 五线 SPI（含 DATA_READY 通知线）与 GD32E508 建立带会话、序号、 信用流控和 CRC32 校验的可靠链路，是所有跨芯片业务的唯一通道。

③ 电机总线控制面：把 HTTP/BLE 请求翻译成 GD32 上三路 CAN/CANFD 收发（单帧、批量、跨通道同步突发、 只听模式），并周期回收电机状态、ADC、版本等遥测，通过网页控制台呈现。

5.6 序号 / 会话失配与「偷读」修复

机制规则
seq 推进发送成功且非陈旧读 → m_txSeq++；poll 读到 ACK/WAIT/ERROR 且 ack_seq==lastSent → 推进；WAIT 也必须推进（否则同 seq 重发被判重，feedTask 卡首 chunk）
迟到响应偷读poll 超时放弃后 GD32 迟到响应拉低 PB6 被 worker 按铃读走（帧已上时钟无法退回）→ 同样必须推进 seq（0.4.2 修复，否则下条命令复用旧序号被 GD32 判重吞掉，业务永远读到旧 0x82）
失配帧处理CRC+session 合法的 RESPONSE 一律交调用方（帧已被读走、GD32 已清 pending，丢弃会死等），由 m_lastRxAckMatched 标记归属，业务以结构化 payload 终判
session 失配EVENT 帧放行；session=0 的响应放行（GD32 重启语义）并置重同步；其余拒收且不更新 credit
撕裂诊断ring_steal_diag：偷读计数/最后类型/ack 归属/payload 签名 [rxLen, rb0, rb1]（0xE8 撕裂时 rb0=A5 rb1=5A 为期望值，255=未找到 SOF）；0x82 归因 rsp_err_last_req/p0..p5，全部进 /system/status

6. 安全握手与加密算法（GD32 OTA 数据面）

GD32 固件转发采用预共享主密钥 + 挑战-应答派生会话密钥，会话内数据 AES-128-ECB 加密。实现于 OtaRelay::doChallengeAndAuth() 与 Protocol（nonce 搅拌生成 / 会话密钥管理）。

Nonce 搅拌算法（scrambleGenerate）：非标准 KDF，仅作握手 nonce——以 tick 计数、栈地址、固定种子 0x12345678 三输入混合每次开机由硬件 RNG 随机生成的 16B 扰码常数，输出 16B。协议实现另有 PC 端 golden-vector 自测（SPI_LINK_V2_SELFTEST）交叉锁定帧字节。

7. OTA 体系（协调器 / 中继 / 本机 / 存储）

7.1 OtaCoordinator — 系统级 9 状态协调器

单例 + FreeRTOS 互斥（100ms 锁超时），是 WiFi/BLE 传输层到 OTA 执行体的唯一权威入口；同时承担忙态看门狗自愈、epoch 会话保护、BLE 射频共存通知、CAN 反馈暂停与电机 OTA 互斥。

7.2 OtaRelay — GD32 转发事件驱动状态机（7 状态）

独立任务（栈 2560B）+ dispatch/result 队列（深度 4）。收到调度信号先 setSuppressRingService(true)（防 SPI worker 把 OTA 响应当 EVENT 偷读——线上事故根因），全程 RAII 持有抑制引用。

步骤实现要点

7.5 Gd32FlashStore — 存储层

能力实现细节
按需擦除（水位）beginWriteSession(false) 复位水位；ensureErasedForWrite 仅从水位向高地址顺序擦 4KB 扇区（跳空一并擦），禁止重擦已写扇区；每扇区擦后喂狗+yield 让 WiFi/LWIP 有机会运行
整区强制擦除电机 OTA 上传 beginWriteSession(true) 全擦 252KB——NOR「只能 1→0」与残留固件叠加会造成静默单 bit 翻转（实测 0x19→0x18 根因）
NVS 元数据命名空间 ota_meta：total_size / stored_size / last_seq / checksum(blob 32B)；读-改-写全程持锁防丢失更新；仅 ACK checkpoint 持久化（NVS commit 毫秒级，不能每包一次）
SHA-256收流收尾统一 metaFinalizeChecksum；relay 门控：checksum 非全零则信任跳过二次全盘 SHA；全零则兜底 metaVerifyChecksum（全零不容忍，防 meta 被清零掩盖损坏）
对齐缓冲OTA 会话 begin 时 calloc(4KB+8)，end/abort 释放——消除每非对齐块 malloc/free 堆抖动，非 OTA 期零占用

7.6 包级防呆：固件身份校验（0.3.81）

SHA-256 只能证明「传对了」，不能证明「传的是对的包」。把 BOOT 包（或 ESP32 镜像/任意文件）中继进 GD32 APP 区会擦掉好固件。validateStoredImageIdentity() 读分区头 8B Cortex-M 向量表：初始 MSP 必须落在 GD32 SRAM（0x20000000~0x2001FFFF）；复位向量（清 Thumb 位）落在 APP 区 → kApp 放行；落在 BOOT 区（0x08000000~0x08011FFF）→ kBootloader 拒绝；判据与 GD32 BOOT 侧 validateApplication() 完全一致（两侧需同步修改）。/ota/relay 与 BLE 0xF7 都强制 kApp 才放行（BLE 错误码 0x87 ERR_FW_IDENTITY）。

10. CANFD 桥接（0xC0~0xC8）

ESP32 不直接接触 CAN 总线：HTTP/BLE 请求翻译为 SPI 命令，GD32 驱动三路 TCAN1057AV 收发器。帧约定 [通道 1B][扩展 ID 4B 大端][数据 0~64B]。

10.1 命令族

TYPE名称载荷 / 行为
0xC0CAN 单帧发送req = ch + id(4B BE) + data（最短 5B，DLC=0）；GD32 回 ACK 或错误码 E0~E7（payload[0]）
0xC1统计 + ID 快照页req=[ch,page]；resp = 28B 固定头（含 mode/snapshot_seq/rx/tx/rx_drop/error/tec/rec/bus_state）+ 条目 (8+dlc)=id 4LE+dlc+flags(FD/BRS/ESI)+rsv+data；快照上限 16 条，page0=条目 0~7、page1=8~15；GD32 亦可 1Hz 主动推送（现默认请求驱动，§12.2）
0xC2设置接收模式0=全收 · 1=按 ID/掩码过滤 · 2=CAN0→CAN1/CAN2 桥接（每帧按原格式自动转发）；回实际生效模式
0xC3ID 快照完整版固定头 4B + 条目 (16+dlc)，含 seq/rx_count；响应可长，不进短响应读预算白名单
0xC7跨通道突发发送多电机同步：4B 头 [count][dlc][suffix_hi][suffix_lo] + count×(chnode(1B=(ch<<4)|node)+data)；单次 ≤16 帧（容量 = min(16,(236−4)/(1+dlc))）
0xC8收发器 Silentreq=[ch, silent 0/1]；回 [ch 回显][actual][ch_en]；错误 E0 过短/E1 通道非法/E2 S 脚回读不符（标志已回滚）

10.3 0xC0 错误码（GD32 细分）

码含义ESP32/HTTP 处理
E0payload 过短（<5B）参数错误

11. 电机 OTA 中继（0xD0~0xD2）

电机节点固件（≤48KB）经 GD32 的 CAN 总线二次烧写。两段式：前端先上传到 gd32_ota 分区（与 GD32 固件共用，上传前 abortCurrent + 清 meta + 整区强制擦除），再触发 relay 由 feedTask 经 SPI 喂给 GD32。

19. 安全审计与已知限制

2026-08-16 安全审计结论（待整改）：当前固件面向可信局域网设计，存在以下已知风险—— ① 零认证：HTTP 22 个端点全部无鉴权（含固件上传、重启、CAN 发送），仅靠局域网边界；Bearer token 方案已设计未实施。 ② 凭据硬编码：WiFi SSID/密码、MASTER_KEY 占位值（01 23 45 67 89 AB CD EF FE DC BA 98 76 54 32 10）明文入仓，建议迁 NVS/Kconfig 并做 CI 扫描。 ③ 无固件签名：ESP32 侧仅 SHA-256 完整性校验（非来源认证）；GD32 侧依赖预共享 MASTER_KEY 的挑战-应答（对称密钥，ESP32 泄露即整链泄露）。 ④ AES-ECB 模式：OTA 数据包逐 16B 块独立加密（确定性模式），相同明文块产生相同密文块。 缓解现状：BLE 需物理接近；GD32 固件包身份校验防误刷；nonce 每会话随机绑定防重放；诊断统计（0x82 归因/偷读签名/熔断计数）全部可观测。

其他工程性限制：SPI 13.33MHz 为实测上限（≥16MHz 全双工不可行；12M 与 13.33M 重发率相当，时钟非重发主因）；Flash 必须 DIO（QIO 读回 SHA 必错）；CANFD 数据字段 64B 不可压缩（用户明确使用长帧）；GD32 包修复依赖三工程协议同步（spi_link/ 兄弟目录 + 两侧判据成对修改）。

2026-10-19 复核更新（专家评审，基线 af1f682 / v0.5.2）：上方 2026-08-16 四项结论原文保留，复核结果如下——
① 零认证：仍存在，且发现 /spi/send 可原样透传任意 SPI 帧类型、timeout_ms 无上限，升级为致命（评审 F-01 / S-12）。
② 凭据硬编码：仍存在，且 STA 口令为真实口令、已进入 git 历史，需轮换（S-08）。
③ 无固件签名：仍存在；另发现 ESP32 回滚保护取消过早、回滚开关所在 config/sdkconfig.defaults 未被构建引用（S-01 / S-02）。
④ AES-ECB：仍存在。
“缓解现状”中“nonce 每会话随机绑定防重放”不成立：nonce 仅 4 字节 tick 变化且明文写入日志（S-06）。新增：BLE GATT 无配对/加密（S-09）。
